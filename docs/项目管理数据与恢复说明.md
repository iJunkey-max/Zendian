# 项目管理数据与恢复说明

## 项目身份与目录

项目由 `.home` 文件中的 `projectId` 识别，目录是当前位置。新项目直接建立身份；旧项目使用“项目检查与关联”登记，登记前备份原始管理数据。扫描项目不会自动改名、移动或删除旧笔记。

知识库内任意层级的项目主页均可发现。重复 ID、同目录多个主页和嵌套项目会标记冲突，不任意挑选一份。项目移出知识库后保留位置记录；无身份的项目可通过预览确认后恢复原身份。

分类和显示名称可以在概览中的“编辑项目属性”调整，不要求移动文件夹。项目阶段由用户维护；任务完成率仅按任务计算。

新建项目的编号可以留空。存放目录留空时使用分类默认目录，输入 `/` 则将新项目文件夹建在知识库根目录；也可以填写 `工作/2026` 等相对父目录。现有文件夹使用“登记现有文件夹”，不会搬动原有资料。嵌套项目不受支持，创建和导入会拒绝与已有项目重叠的位置。

## 任务与动态

项目任务存放在项目主页中，普通 Markdown 待办不会自动汇总。任务通过稳定 ID 修改；创建、完成、取消完成和删除保留业务记录。今日任务数以当前完成任务的完成时间计算。

任务关联使用项目内相对文件路径；Obsidian 已确认的项目内改名会更新引用，扫描发现的相似内容不会自动改写。原文件缺失时仍可修改任务，编辑关联路径或留空解除。跨项目移动或关闭期间的改名可能需要手动重新关联。

交付清单的添加、更新和移除保存为独立历史，移除清单记录后仍可查看动态。旧清单首次建立的记录会标为近似时间基线。项目阶段历史与任务活动同样保留，但不能据此推断未通过插件发生的所有操作。

里程碑也保留新增、修改、完成、重新打开和移除记录。计划日期单独展示，不当作实际操作时间；旧里程碑首次建立的动态只是基线。旧 Timeline 和元数据接口的里程碑按来源区分，同名项目不会被自动合并。

交付发布使用项目自身分类的目录配置；未分类或该分类未配置目录时，默认存放在项目内的 `交付物` 文件夹。无需先配置分类才能发布。无效目录名称需要在设置中修正；当前目录和已登记的旧交付目录不会作为发布源文件。

删除发布包时按记录的项目内路径定位，并核对 ZIP 内发布身份，不要求旧包仍位于当前分类目录。校验或移入回收站失败时保留项目记录；若 ZIP 已进入回收站而记录保存失败，会明确提示，可从回收站恢复。没有可验证发布清单的旧 ZIP 需要手动核对，插件不会直接删除。

单次交付源文件总量上限为 256 MB。发布会核对源文件读取前后的路径、大小和修改时间，并在生成包后保存项目记录；这是两次文件写入，不是磁盘事务。主页记录保存失败时，ZIP 会保留并报告位置，请核对该包与主页后处理，不要重复使用同一发布名称。

文件核对记录使用扫描发现时间，不代表精确操作时间。启动时重新校验不超过 8 MB 文件的指纹，后续核对复用属性未变的指纹；更大的文件使用大小和修改时间。关闭期间的中间修改过程无法还原，相同内容的新增/缺失只提供可能移动的提示。

## 历史与备份范围

项目位置、文件核对和快照历史目前保存于知识库配置目录的 `plugins/zendian/` 中。复制项目文件夹可以携带当前管理信息和任务，但不会自动携带该目录中的快照历史。应同时备份配置目录，或使用项目迁移包。

检查点只覆盖快照服务支持的文本文件，不是完整磁盘备份。恢复前显示覆盖、补回和保留范围，并创建安全检查点；默认保留之后新增的文件。恢复部分失败时应检查结果提示。

文本快照单文件上限为 1 MiB，支持 Markdown、Canvas、JSON、主页及部分代码和配置文本；图片、PDF 等二进制不在检查点恢复范围。项目主页恢复工作内容时保留当前身份和已有操作历史，并追加恢复记录。当前文件无法备份、历史内容校验失败或提交前文件被修改时停止该文件恢复；多个文件不是一个磁盘事务，可能部分成功。

历史索引损坏或版本不兼容时，历史服务停止读取及写入，不会用空历史替换原索引，并尝试在同目录保存 `index.corrupt-<时间>.json` 副本。请先备份整个历史目录，再从有效备份恢复索引，之后重新加载插件。自动副本写入也可能失败，应以实际文件为准；不要手动删除内容 Blob 来修复索引。

运行期间保存历史前也会比较磁盘索引。发现外部修改或写入失败后，当前实例停止历史操作，避免继续使用未提交的内存状态；请等待同步完成、确认存储可写后重新加载。该比较不是跨设备文件锁，无法保证识别“比较完成到写入之间”发生的同步覆盖。

## 迁移包

交付页的“补登记已有发布包”用于 ZIP 生成成功而主页记录保存失败。输入项目内 ZIP 路径，校验通过后仅补写记录，不重新生成包。新包优先核对稳定项目 ID，项目移动后仍可识别；其他身份及独立副本不自动认领。缺少身份的旧包按原项目路径核对。

项目导出菜单提供迁移包，包含项目目录内文件和可选快照历史，不包含项目目录外的链接文件。包内清单明确标记历史范围。单次项目文件导出上限为 256 MB，导入包上限为 512 MB。

首页项目菜单或命令面板可以导入。目标必须是新目录；独立副本生成新的项目 ID。保留身份时检测知识库中是否已有相同 ID。导入失败会保留已写入的新目录并报告位置，不覆盖已有目录；项目主页最后发布，避免未完成内容被提前识别为项目。

导入支持本插件导出的未压缩 ZIP，预检文件校验值、完整目录、清单范围和可移植路径。不能把任意第三方 ZIP 当作项目包导入。导出期间检测到文件集合、大小或修改时间变化会要求重试；包含历史后的包仍需满足 512 MB 上限。

## 已知验证边界

活动与专注日志无法读取、保存失败或检测到外部更新时，当前实例停止日志写入并提示。新记录可能只存在内存中；请先备份 `activity-log.json` 及损坏副本，核对存储和同步，再重新加载。插件不会以空日志覆盖不可读原文件；写前比较也不能替代跨设备文件锁。

自动化测试使用模拟 Vault，已覆盖身份、路径核对、任务并发、外部修改冲突、包往返和恢复规则。多设备同步、移动端、复杂恢复失败、深浅色及窄窗口仍需对应实机证据；本说明不代表整体重构已验收完成。
