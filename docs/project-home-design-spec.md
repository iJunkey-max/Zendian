# ZENdian 项目主页设计规范

## 设计定位

项目主页是一个项目工作文档，不是把所有统计信息平铺出来的仪表盘。首屏只回答三个问题：

1. 这是什么项目，当前处于什么阶段？
2. 项目目标是什么？
3. 下一步最应该推进哪一个具体动作？

项目任务、交付物、动态、数据和文件是同一个项目工作区的不同视图，不在概览页重复堆叠。

## 参考方法与取舍

- Linear 的项目概览将摘要、属性、文档和里程碑作为项目身份的一部分，并将项目详情放进可收起的侧栏；ZENdian 采用同样的“正文优先、属性侧栏化”思路。
- Todoist 使用项目区段/阶段组织长任务流，让任务列表保持可读；ZENdian 将“下一步行动”作为概览页的短清单，完整任务仍进入任务视图。
- Basecamp 的项目首页只突出少量重要工具或 Spotlight，具体工作进入独立工具页；ZENdian 不在概览页同时渲染完整交付物、动态和文件列表。

## 页面骨架

```text
项目路径
└─ 项目身份：图标 / 名称 / 类型 / 创建时间 / 截止时间 / 当前阶段 / 导出
   └─ 工作区标签：概览 / 任务 / 交付物 / 动态 / 数据 / 文件
      ├─ 主文档面：项目目标、当前推进、下一步行动
      └─ 窄侧栏：项目节奏、阶段进度、任务/交付物/文件摘要、近期活动
```

## 视觉规则

- 使用 Obsidian 原生背景、文字、边框和强调色变量，不硬编码主题色。
- 页面只有一个主要内容面；二级视图采用相同的标题栏、内容面、行式列表和表单底栏。
- 取消霓虹色、装饰渐变、发光边框、无业务意义的编号和重复统计卡。
- 圆角用于内容面和控件，不用于把每一行内容包成独立卡片；列表使用分隔线建立节奏。
- 主要按钮只保留一个强调层级，编辑、导出、切换和删除保持低强调。
- 首屏信息顺序优先于视觉装饰；空状态必须给出下一步动作。

## 组件复用

- `createSharedPanelShell`：项目详情、列表、设置与独立面板的标题栏和内容面。
- `createSharedContentShell`：项目控制台各标签页的标题栏和正文面。
- `createSharedFormShell`：新建/编辑任务、快速便签、导入、发布、快照和新窗口表单。
- `css/overlays/project-home-redesign.css`：项目主页及其二级面板的最终视觉层。

## 实现边界

视觉重构不改变项目身份、任务同步、交付物发布、快照恢复、时间轴和专注归属逻辑。所有动态数据仍由现有服务层提供，渲染层只调整信息组织和视觉层级。
